# Step 4：过滤、上下文预算和 dry-run

## 任务与验收

1. 敏感路径与文本过滤：新增/修改敏感文件在调用 Codex 前停止；删除仅元数据；普通文件前后版本、历史和输出识别凭据。测试旧行、未跟踪、秘密重复出现、终端控制字符及安全错误。
2. Prompt 与预算：仅使用净变化；先过滤，再编码与计量。完整文本超限时裁去相同前后行，保留整个变化区间和相邻三行；仍超限停止。JSON Schema 只允许 format/type/scope/subject/body，CLI 校验语义并组合消息。
3. 接通 dry-run：读取、过滤、Codex、结果校验、快照复核、展示覆盖范围与建议；超时与信号取消，无 Git 写操作或 hooks。默认命令仍明确提示后续步骤未实现。
4. 一次独立评审，重要问题一轮测试先行修复；pnpm check、真实合成仓库 dry-run、打包后脱离源码安装验证。

## 接口预检

- GitContext → 过滤：不发送 staged/unstaged 原始 patch、仓库绝对路径、OID 或摘要；仅净变化前后版本和过滤后的历史。
- 过滤 → Prompt：检测到的秘密同时用于所有文本的替换和模型输出的检查；覆盖信息显式列出内容/元数据范围。
- Prompt → Codex：完整用户 Prompt 的 UTF-8 字节受 maxContextBytes 限制，Schema 由适配器另行限制；结构与语义分别校验。
- Codex → dry-run：快照失效、响应非法、取消均不展示建议。

## 执行记录

- Ruling: 仓库无 HEAD，沿用当前独立仓库和分支；以本步 tar 基线和本文件替代提交区间脚本，不创建提交。代价：评审按文件差异定位。
- Ruling: Git 原始采集预算与模型预算分开；dry-run 在现有硬上限 1 MiB 内采集，单文件仍遵守配置，然后按发送预算压缩。代价：极大仓库仍可能在压缩前被安全拒绝。
- Ruling: 不新增 Diff 依赖；中等上下文裁剪每文件共同前缀和后缀，保留中间所有行与行号，并明确不是最小 Diff。代价：多处分散修改可能较早超限，但不丢弃任何修改行。
- Ruling: 敏感路径无模板例外（包括 .env.example）；文本规则为保守的常见凭据检测，不承诺识别任意秘密。代价：可能误拦模板；未匹配的业务敏感信息需使用者自行判断。
